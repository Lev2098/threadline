# QA: як перевірявся продукт

[← README](../../README.md) · [Русский](../ru/qa.md)

Після релізу 1.0.0 продукт незалежно перевірили чотири QA-агенти на живому стеку з 1 000 000 коментарів:

| Напрям | Що робили |
|---|---|
| API та безпека | Фазинг XSS (сутності, лапки, `javascript:` з обфускацією), капча (повтор, гонка, кирилиця), завантаження (поліглоти, decompression bomb, анімовані GIF, MPO, межа 100 КБ), JWT (`alg=none`, підпис, термін дії), параметри, формат помилок |
| Інтерфейс у браузері | Chrome через CDP: сортування й історія, пагінація, гілки на 15 рівнів, форма, live-оновлення з двох клієнтів, lightbox, пошук, UA/RU, тема, 390/768/1280 px, клавіатура, контраст, консоль |
| Дані та інфраструктура | SQL-звірка цілісності всіх 1M рядків, конкурентні відповіді й корені, кеш, межі глибини дерева, падіння брокера та Elasticsearch, пул з'єднань, graceful shutdown, nginx |
| Відповідність ТЗ і документація | Кожен пункт ТЗ, перевірка команд у документації, «чистий» `git clone`, інструкція деплою, UA ↔ RU |

## Результат

- **Чого не знайшли.** Обходу XSS-захисту, SQL-ін'єкцій, проблем із JWT і неконсистентних даних на мільйоні рядків.
- **Що знайшли й виправили.** ~60 знахідок; кожна підтверджена має регресійний тест (`tests/*/test_qa_regressions.py`).

### Найважливіші виправлення

| Знахідка | Виправлення |
|---|---|
| Кирилиця в полі капчі давала 500 | Порівняння лише ASCII; на клієнті перевірка латиниці й цифр |
| Інструкція деплою лишала сайт неробочим: healthcheck на `127.0.0.1` відхилявся через `ALLOWED_HOSTS` | `/healthz` відповідає до перевірки Host |
| За Caddy усі клієнти мали одну IP: спільні на весь сайт ліміти, хибний IP у БД | nginx довіряє `X-Forwarded-For` лише від фіксованої адреси Caddy |
| Брокер недоступний → 500 для вже збереженого коментаря | Inline-fallback після commit; push і індексація — окремі задачі |
| Elasticsearch недоступний → HTML 500 після 15 с | JSON 503 за ≤ 2 с |
| CPU-DoS через анімований GIF, ліміт пікселів фактично 80 Мп | Ліміти кадрів і пікселів до декодування |
| Засмічення Redis довільними курсорами гілки | Строга валідація курсора, кешується лише перша порція |
| GraphQL без лімітів, 40 аліасів = 40× роботи | Ліміти глибини, аліасів, токенів; GraphiQL лише в DEBUG |
| Глибока гілка на телефоні: картки по 28 px | Відступ зупиняється після 3 рівнів (8 на десктопі) |
| Гонки відповідей: таблиця показувала інше сортування | Застарілі відповіді ігноруються (list, search, preview) |
| Неоднорідний формат помилок, англійські повідомлення в UI | Єдиний JSON для всіх помилок, переклад UA/RU у клієнті |
| Контраст нижче WCAG AA | Токени кольорів виправлені для обох тем |

### Свідомо не змінено

| Знахідка | Чому |
|---|---|
| E-mail видно в API | ТЗ вимагає таблицю з колонкою та сортуванням за E-mail |
| Ширина сегмента шляху 10 цифр | Вистачає на 10¹⁰ коментарів; переповнення явно відхиляється, а не ламає порядок |
| Міграція індексів без `CONCURRENTLY` | Виконується до старту застосунку; на робочій базі з мільйонами рядків варто перейти на `AddIndexConcurrently` |
| Кешування при ввімкненій read replica може брати дані з відстаючої репліки | Репліка в поставці вимкнена; описано в [scaling.md](scaling.md) як наступний крок |
| Тестувальник: «посилання з `target="_blank"` — це XHTML Transitional, а не Strict» | Безпечне відкриття зовнішніх посилань у новій вкладці важливіше; розмітка лишається валідною XHTML 1.0 Transitional |
