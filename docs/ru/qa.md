# QA: как проверялся продукт

[← README](../../README.ru.md) · [Українська](../uk/qa.md)

После релиза 1.0.0 продукт независимо проверили четыре QA-агента на живом стеке с 1 000 000 комментариев:

| Направление | Что делали |
|---|---|
| API и безопасность | Фаззинг XSS (сущности, кавычки, `javascript:` с обфускацией), капча (повтор, гонка, кириллица), загрузки (полиглоты, decompression bomb, анимированные GIF, MPO, граница 100 КБ), JWT (`alg=none`, подпись, срок действия), параметры, формат ошибок |
| Интерфейс в браузере | Chrome через CDP: сортировка и история, пагинация, ветки на 15 уровней, форма, live-обновления с двух клиентов, lightbox, поиск, UA/RU, тема, 390/768/1280 px, клавиатура, контраст, консоль |
| Данные и инфраструктура | SQL-сверка целостности всех 1M строк, конкурентные ответы и корни, кэш, границы глубины дерева, падение брокера и Elasticsearch, пул соединений, graceful shutdown, nginx |
| Соответствие ТЗ и документация | Каждый пункт ТЗ, проверка команд в документации, «чистый» `git clone`, инструкция деплоя, UA ↔ RU |

## Результат

- **Чего не нашли.** Обхода XSS-защиты, SQL-инъекций, проблем с JWT и неконсистентных данных на миллионе строк.
- **Что нашли и исправили.** ~60 находок; у каждой подтверждённой есть регрессионный тест (`tests/*/test_qa_regressions.py`).

### Самые важные исправления

| Находка | Исправление |
|---|---|
| Кириллица в поле капчи давала 500 | Сравнение только ASCII; на клиенте проверка латиницы и цифр |
| Инструкция деплоя оставляла сайт нерабочим: healthcheck на `127.0.0.1` отклонялся из-за `ALLOWED_HOSTS` | `/healthz` отвечает до проверки Host |
| За Caddy у всех клиентов был один IP: общие на весь сайт лимиты, неверный IP в БД | nginx доверяет `X-Forwarded-For` только от фиксированного адреса Caddy |
| Брокер недоступен → 500 для уже сохранённого комментария | Inline-fallback после commit; push и индексация — отдельные задачи |
| Elasticsearch недоступен → HTML 500 через 15 с | JSON 503 за ≤ 2 с |
| CPU-DoS через анимированный GIF, лимит пикселей фактически 80 Мп | Лимиты кадров и пикселей до декодирования |
| Засорение Redis произвольными курсорами ветки | Строгая валидация курсора, кэшируется только первая порция |
| GraphQL без лимитов, 40 алиасов = 40× работы | Лимиты глубины, алиасов, токенов; GraphiQL только в DEBUG |
| Глубокая ветка на телефоне: карточки по 28 px | Отступ останавливается после 3 уровней (8 на десктопе) |
| Гонки ответов: таблица показывала другую сортировку | Устаревшие ответы игнорируются (list, search, preview) |
| Неоднородный формат ошибок, английские сообщения в UI | Единый JSON для всех ошибок, перевод UA/RU в клиенте |
| Контраст ниже WCAG AA | Токены цветов исправлены для обеих тем |

### Сознательно не изменено

| Находка | Почему |
|---|---|
| E-mail виден в API | ТЗ требует таблицу с колонкой и сортировкой по E-mail |
| Ширина сегмента пути 10 цифр | Хватает на 10¹⁰ комментариев; переполнение явно отклоняется, а не ломает порядок |
| Миграция индексов без `CONCURRENTLY` | Выполняется до старта приложения; на рабочей базе с миллионами строк стоит перейти на `AddIndexConcurrently` |
| Кэширование при включённой read replica может брать данные с отстающей реплики | Реплика в поставке выключена; описано в [scaling.md](scaling.md) как следующий шаг |
| Тестировщик: «ссылки с `target="_blank"` — это XHTML Transitional, а не Strict» | Безопасное открытие внешних ссылок в новой вкладке важнее; разметка остаётся валидным XHTML 1.0 Transitional |
